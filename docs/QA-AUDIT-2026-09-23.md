## Runtime routing correction

A runtime issue was found after the initial static QA: `product.html` registered `renderDetail` as the DOMContentLoaded callback **before** `assets/site.js` had loaded, so clicking a product could open the product template with an empty detail area.

Fixed in commit `87e901d1fb3883eff924691756538fbd4aecc397` by loading `assets/catalog.js` and `assets/site.js` first, then registering `() => renderDetail()`.

Post-fix routing QA:
- detail container appears before scripts;
- catalogue script loads before site script;
- renderDetail listener is registered only after site script;
- all 41 completed product-detail records (12 Highland Cow + 29 Peter Rabbit) have slug, label and image data;
- all primary and gallery image references for those records resolve;
- no JS syntax errors detected in catalogue/site scripts.

This supersedes the earlier statement that no blocking issue existed before runtime navigation was checked.
