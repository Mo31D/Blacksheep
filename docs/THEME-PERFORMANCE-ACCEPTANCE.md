# Theme performance and acceptance — 29 September 2026

Source safeguards: `assets/site.js` fetches published Appearance after the storefront starts and inserts the optional layer once only for enabled Winter/Christmas. It removes the layer when disabled and falls back if the stylesheet fails. Browsers reporting Save-Data or at most 2 GiB device memory skip it entirely. At widths up to 760px, the layer removes the large shadow and reduces the motif. At 480px and below, it hides the motif and image inset. Seasonal art has no animation or interaction; the base stylesheet's `prefers-reduced-motion: reduce` rule disables existing site motion.

Transfer budget before compression: optional CSS is under 6 KiB; each original SVG is under 4 KiB. Current measured source sizes are approximately 3.2 KiB CSS, 864 B Winter SVG and 1,034 B Christmas SVG. Neither SVG contains scripts, embedded images or external asset references. The two images are requested by CSS only for their matching theme; no decorative assets are part of the default theme. Unit tests enforce the budget and gating.

Local acceptance: actual homepage and Full range HTML were rendered with both preset token sets and optional layer in a temporary local fixture; 1280px browser viewport showed legible content, distinct seasonal identity, no horizontal document overflow and no console errors. Generated Admin script, public Appearance contract, dynamic storefront, TypeScript and full Commerce tests pass. The fixture does not prove remote staging or a low-memory physical device. Deployed staging review of Admin preview/publish, mobile screen sizes and network timings remains a manual release action after an authorized staging deployment of Worker migration 0025. No synthetic order, email, D1 or R2 writes were made for this review. A production Worker deploy or production-data mutation still requires explicit approval.
